# 项目启动准备

## 范围结论

- 一期 MVP 先收敛到认证、简历、岗位、分析、报告、历史记录
- 管理后台先做最小能力，优先 API 日志、任务日志、Prompt 模板管理
- AI 先做 `resume_parse`、`job_parse`、`full_analysis` 三个场景

## 技术结论

- 后端：`Python 3.12 + FastAPI + SQLAlchemy + Alembic + PostgreSQL`
- 前端：`Vue 3 + Vite + TypeScript + Pinia + Vue Router + Axios + Element Plus`
- 部署：开发环境优先 `backend + PostgreSQL`，生产环境优先 `Nginx + Backend + PostgreSQL`

## 当前已落地

- 根目录环境文件：`.env.example`、`.env.dev`
- 开发编排：`docker-compose.yml`
- 后端基础文件：配置、数据库、鉴权基础、异常处理、统一响应、健康检查
- 前后端目录骨架、AI 目录、迁移目录、部署目录、日志目录、数据目录

## 已识别的文档差异

- 健康检查路径文档同时出现 `GET /health` 与 `GET /api/health`
- 当前脚手架已同时兼容两种访问方式，后续建议统一成一个对外约定
- 管理后台在需求、任务拆解、API 文档中的范围略有膨胀，建议按“最小后台能力”推进

## 推荐开发顺序

1. 核心数据表与 Alembic 首个 migration
2. 鉴权与用户基础信息
3. 简历上传、文件保存、文本解析
4. 岗位录入与结构化解析
5. Prompt 模板与 DeepSeek 服务封装
6. 分析任务、报告生成、历史记录
7. 前端主链路页面联调
8. 最小管理后台
