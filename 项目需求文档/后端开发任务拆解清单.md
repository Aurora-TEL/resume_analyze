# 简历分析系统后端开发任务拆解清单

## 1. 文档说明

### 1.1 文档目的

本文档用于将简历分析系统后端开发工作拆解为可执行任务，帮助开发过程按阶段推进、按接口验收、按模块联调。

本文档重点覆盖：

- FastAPI 后端项目初始化
- PostgreSQL 数据库模型与迁移
- 用户认证与权限校验
- 简历上传与解析
- 岗位描述管理
- DeepSeek AI 调用封装
- Prompt 模板管理
- 分析任务执行
- 分析报告保存与查询
- API 调用日志
- 本地 Docker 联调

### 1.2 MVP 开发目标

一期 MVP 优先跑通主流程：

```text
用户注册 / 登录
  ↓
上传简历
  ↓
新建岗位描述
  ↓
发起完整分析任务
  ↓
调用 DeepSeek
  ↓
生成分析报告
  ↓
前端查看报告
```

### 1.3 一期优先实现范围

一期优先实现以下能力：

1. 用户注册、登录、获取当前用户信息。
2. 简历上传、文本提取、简历列表和详情。
3. 岗位描述创建、列表和详情。
4. Prompt 模板初始化和读取。
5. DeepSeek API 调用封装。
6. 完整分析任务 `full_analysis`。
7. 分析报告保存和查询。
8. API 调用日志记录。

一期暂缓实现：

1. 管理后台完整功能。
2. 异步任务 Worker。
3. Redis 队列。
4. 单独的评分接口、关键词接口、改写接口。
5. 报告导出。
6. 在线简历编辑器。

# 4. 阶段 3：用户认证模块

## 4.1 目标

实现用户注册、登录、JWT 鉴权和当前用户信息获取。

## 4.2 需要实现的接口

```text
POST /api/auth/register
POST /api/auth/login
GET /api/auth/me
POST /api/auth/logout
```

## 4.3 核心任务

### 4.3.1 密码安全

任务清单：

-  在 `core/security.py` 中实现密码哈希。
-  使用 `passlib[bcrypt]`。
-  实现 `verify_password`。
-  禁止保存明文密码。

### 4.3.2 JWT 生成与校验

任务清单：

-  实现 `create_access_token`。
-  Token 中包含 `sub=user_id`。
-  支持过期时间配置。
-  实现 `get_current_user` 依赖。

### 4.3.3 注册接口

任务清单：

-  校验邮箱格式。
-  校验密码长度不少于 8 位。
-  校验邮箱唯一。
-  创建用户。
-  返回 Token 和用户信息。

请求示例：

```json
{
  "email": "user@example.com",
  "password": "Password123",
  "nickname": "张三"
}
```

### 4.3.4 登录接口

任务清单：

-  校验邮箱和密码。
-  检查用户状态是否为 `active`。
-  更新 `last_login_at`。
-  返回 Token。
-  登录失败时不暴露账号是否存在。

### 4.3.5 当前用户信息接口

任务清单：

-  从 JWT 中解析用户 ID。
-  查询用户。
-  返回用户基础信息。
-  不返回密码哈希。

## 4.4 验收标准

-  用户可以注册。
-  用户可以登录。
-  登录后可以访问受保护接口。
-  未登录访问受保护接口返回 401。
-  Token 过期返回 401。

# 5. 阶段 4：简历上传与解析模块

## 5.1 目标

用户可以上传 PDF、DOCX、TXT 简历，系统保存文件、提取文本，并调用 DeepSeek 进行结构化解析。

## 5.2 需要实现的接口

```text
POST /api/resumes/upload
GET /api/resumes
GET /api/resumes/{resume_id}
PATCH /api/resumes/{resume_id}
DELETE /api/resumes/{resume_id}
POST /api/resumes/{resume_id}/parse
```

MVP 优先实现：

```text
POST /api/resumes/upload
GET /api/resumes
GET /api/resumes/{resume_id}
POST /api/resumes/{resume_id}/parse
```

## 5.3 文件上传任务

任务清单：

-  在 `.env` 中配置 `UPLOAD_DIR`。
-  在 `.env` 中配置 `MAX_UPLOAD_SIZE_MB`。
-  支持 PDF、DOCX、TXT。
-  校验文件大小。
-  校验文件扩展名和 MIME 类型。
-  生成安全文件名。
-  保存到 `storage/resumes`。
-  保存数据库记录。

## 5.4 文本解析任务

建议实现 `parser_service.py`：

```text
parse_txt(file_path)
parse_docx(file_path)
parse_pdf(file_path)
extract_text(file_path, file_type)
```

任务清单：

-  TXT 使用普通文本读取。
-  DOCX 使用 `python-docx`。
-  PDF 使用 `pypdf` 或 `pdfplumber`。
-  保留段落换行。
-  解析失败时写入 `parse_error`。

## 5.5 简历结构化解析任务

任务清单：

-  上传成功后先提取 `raw_text`。
-  调用 `resume_parse` Prompt。
-  将返回结果保存到 `resumes.structured_data`。
-  更新 `parse_status=success`。
-  AI 调用失败时保留文件记录，并设置 `parse_status=failed`。

MVP 可选策略：

```text
上传接口只做文件保存和文本解析。
结构化解析由 /api/resumes/{resume_id}/parse 单独触发。
```

这样上传接口响应更快，也便于失败重试。

## 5.6 查询接口任务

任务清单：

-  简历列表支持分页。
-  简历列表不返回 `raw_text` 大字段。
-  简历详情返回 `raw_text` 和 `structured_data`。
-  只能查询当前用户自己的简历。

## 5.7 验收标准

-  用户可以上传 TXT 简历。
-  用户可以上传 DOCX 简历。
-  用户可以上传 PDF 简历。
-  文件超限时返回错误。
-  不支持的文件类型返回错误。
-  可以查看简历列表。
-  可以查看简历详情。
-  可以重新解析简历。

# 6. 阶段 5：岗位描述模块

## 6.1 目标

用户可以创建岗位描述，系统保存岗位原文，并调用 DeepSeek 解析结构化岗位要求。

## 6.2 需要实现的接口

```text
POST /api/jobs
GET /api/jobs
GET /api/jobs/{job_id}
PUT /api/jobs/{job_id}
DELETE /api/jobs/{job_id}
POST /api/jobs/{job_id}/parse
```

MVP 优先实现：

```text
POST /api/jobs
GET /api/jobs
GET /api/jobs/{job_id}
POST /api/jobs/{job_id}/parse
```

## 6.3 创建岗位任务

任务清单：

-  校验岗位名称不能为空。
-  校验岗位描述正文不能为空。
-  保存岗位描述记录。
-  默认 `parse_status=pending`。
-  可选：创建后立即调用 `job_parse`。

请求示例：

```json
{
  "title": "Python 后端开发工程师",
  "company_name": "某某科技有限公司",
  "industry": "互联网",
  "location": "上海",
  "salary_range": "15k-25k",
  "description_text": "岗位职责：负责后端 API 开发..."
}
```

## 6.4 岗位结构化解析任务

任务清单：

-  调用 `job_parse` Prompt。
-  提取岗位职责、必备技能、加分技能、关键词。
-  保存到 `job_descriptions.structured_data`。
-  更新 `parse_status=success`。
-  调用失败时保存 `parse_error`。

## 6.5 查询接口任务

任务清单：

-  岗位列表支持分页。
-  岗位列表不返回过长的完整正文，可返回摘要。
-  岗位详情返回完整正文和结构化数据。
-  只能查询当前用户自己的岗位描述。

## 6.6 验收标准

-  用户可以创建岗位描述。
-  用户可以查看岗位列表。
-  用户可以查看岗位详情。
-  岗位可以被 DeepSeek 结构化解析。
-  解析失败可以查看错误信息。

# 8. 阶段 7：DeepSeek AI 调用封装

## 8.1 目标

封装统一 DeepSeek 调用逻辑，避免业务代码直接访问 DeepSeek API。

## 8.2 DeepSeekClient 任务

创建文件：

```text
app/services/ai/deepseek_client.py
```

任务清单：

-  从环境变量读取 `DEEPSEEK_API_KEY`。
-  从环境变量读取 `DEEPSEEK_BASE_URL`。
-  从环境变量读取 `DEEPSEEK_MODEL`。
-  实现 chat completion 调用。
-  支持 timeout。
-  捕获网络错误。
-  捕获限流错误。
-  捕获 API Key 错误。
-  返回原始响应和文本内容。

建议方法：

```python
class DeepSeekClient:
    async def chat_json(self, prompt: str, scene: str) -> AIResponse:
        ...
```

## 8.3 ResponseParser 任务

创建文件：

```text
app/services/ai/response_parser.py
```

任务清单：

-  去除 Markdown 代码块。
-  截取 JSON 对象。
-  执行 `json.loads`。
-  解析失败时抛出 `AIResponseInvalidError`。

建议方法：

```python
class ResponseParser:
    def parse_json(self, content: str) -> dict:
        ...
```

## 8.4 ResponseValidator 任务

创建文件：

```text
app/services/ai/response_validator.py
```

任务清单：

-  校验 `resume_parse` 输出。
-  校验 `job_parse` 输出。
-  校验 `full_analysis` 输出。
-  修正越界分数。
-  缺失数组字段时填充空数组。
-  关键字段缺失时抛出错误。

## 8.5 API 调用日志任务

任务清单：

-  每次调用前记录开始时间。
-  调用成功后记录耗时、输入长度、输出长度。
-  调用失败后记录错误类型和错误消息。
-  不记录完整简历原文。
-  不记录完整 Prompt。

## 8.6 验收标准

-  DeepSeekClient 可以独立测试。
-  模型返回 JSON 时能成功解析。
-  模型返回 Markdown 包裹 JSON 时能成功解析。
-  模型返回非法 JSON 时能返回友好错误。
-  `api_call_logs` 能记录成功和失败调用。

# 9. 阶段 8：分析任务与报告生成

## 9.1 目标

实现用户发起分析任务，后端读取简历和岗位，调用 DeepSeek 生成完整报告，并保存到数据库。

## 9.2 需要实现的接口

```text
POST /api/analysis/tasks
GET /api/analysis/tasks/{task_id}
GET /api/analysis/tasks
GET /api/reports
GET /api/reports/{report_id}
```

MVP 优先实现：

```text
POST /api/analysis/tasks
GET /api/analysis/tasks/{task_id}
GET /api/reports/{report_id}
```

## 9.3 创建分析任务接口

请求示例：

```json
{
  "resume_id": "uuid",
  "job_description_id": "uuid",
  "task_type": "full_analysis"
}
```

任务清单：

-  校验简历属于当前用户。
-  校验岗位描述属于当前用户。
-  校验 `task_type`。
-  创建 `analysis_tasks` 记录。
-  MVP 同步执行分析。
-  成功后创建 `analysis_reports` 记录。
-  更新任务状态为 `success`。
-  失败后更新任务状态为 `failed`。

## 9.4 full_analysis 执行流程

建议流程：

```text
创建任务 pending
  ↓
更新任务 running，progress=10
  ↓
读取简历 raw_text / structured_data
  ↓
读取岗位 description_text / structured_data
  ↓
如果简历未结构化解析，先调用 resume_parse
  ↓
如果岗位未结构化解析，先调用 job_parse
  ↓
构建 full_analysis Prompt
  ↓
调用 DeepSeek
  ↓
解析 JSON
  ↓
校验报告结构
  ↓
保存 analysis_reports
  ↓
更新任务 success，progress=100
```

## 9.5 分析服务任务

创建文件：

```text
app/services/analysis_service.py
```

任务清单：

-  实现 `create_analysis_task`。
-  实现 `run_full_analysis`。
-  实现 `ensure_resume_parsed`。
-  实现 `ensure_job_parsed`。
-  实现 `save_analysis_report`。
-  实现失败回滚或状态更新。

## 9.6 报告保存任务

保存字段：

```text
task_id
user_id
resume_id
job_description_id
total_score
match_score
summary
report_data
model_provider
model_name
report_version
```

任务清单：

-  从 AI 返回中提取 `total_score`。
-  从 AI 返回中提取 `match_score`。
-  从 AI 返回中提取 `summary`。
-  完整 JSON 保存到 `report_data`。
-  `task_id` 一对一关联报告。

## 9.7 任务状态接口

任务清单：

-  支持按 task_id 查询。
-  只能查询当前用户自己的任务。
-  返回任务状态、进度、错误信息和 report_id。

响应示例：

```json
{
  "task_id": "uuid",
  "task_type": "full_analysis",
  "status": "success",
  "progress": 100,
  "error_message": null,
  "report_id": "uuid"
}
```

## 9.8 报告详情接口

任务清单：

-  按 report_id 查询报告。
-  只能查询当前用户自己的报告。
-  返回完整 `report_data`。
-  同时返回总分、匹配度、摘要、生成时间。

## 9.9 验收标准

-  用户可以选择简历和岗位发起完整分析。
-  分析任务成功后可以生成报告。
-  报告中包含总分、匹配度、优势、问题、关键词、建议和改写示例。
-  AI 调用失败时任务状态为 `failed`。
-  前端可以通过 report_id 获取报告详情。

-  系统可以调用 DeepSeek 解析岗位结构。
-  用户可以查看岗位列表。
-  用户可以查看岗位详情。

## 13.4 分析链路验收

-  用户可以选择简历和岗位发起分析。
-  系统可以创建分析任务。
-  系统可以调用 DeepSeek 生成完整报告。

-  用户可以查看报告详情。

-  AI 返回合法 JSON 时能正常解析。
-  AI 返回 Markdown 包裹 JSON 时能正常解析。
